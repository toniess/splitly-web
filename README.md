# Splitly — веб-клиент

Фронтенд к [splitly-backend](https://github.com/toniess/splitly-backend): группы,
траты, балансы и план взаиморасчётов.

| Что | Выбор |
| --- | --- |
| Сборка | Vite 7 |
| UI | React 19 + TypeScript |
| Состояние | обычный `useState`, без библиотек |
| Стили | один CSS-файл, тёмная тема |
| Выкладка | GitHub Pages, статика |

Зависимостей ровно две — `react` и `react-dom`. Маршрутизатора нет: экранов
три, переключение состоянием обходится дешевле отдельной библиотеки.

## Запуск

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173` и будет ходить в боевой бэкенд.
Чтобы работать против локального, создайте `.env.local`:

```
VITE_API_BASE=http://localhost:8080
```

## Экраны

**Вход** — регистрация и логин. После регистрации клиент сразу логинится сам:
бэкенд на `/auth/register` возвращает только `userId`, без токенов.

**Группы** — список своих, создание новой, вступление по коду приглашения.

**Группа** — три вкладки:

- *Траты* — лента с курсорной пагинацией и форма добавления. Деление поровну,
  по долям или точными суммами; при равном делении доли считает сервер.
- *Балансы* — сальдо каждого участника. Плюс значит «должны вам».
- *Расчёт* — минимальный список переводов. Кнопка «Я отдал» появляется только
  у того, кто отдаёт: сервер принимает перевод исключительно от отправителя.

## Демо-режим

На экране входа есть кнопка «Посмотреть демо без регистрации». Она включает
песочницу: те же экраны, но данные живут в памяти вкладки и исчезают при
перезагрузке. Сервер не используется вообще.

Так сделано по двум причинам. Neon на бесплатном тарифе засыпает после
простоя, и первый запрос ждал бы пробуждения базы около десяти секунд —
для кнопки «просто посмотреть» это выглядит как сломанный сайт. И не нужно
держать пароль демо-аккаунта в публичном репозитории.

Цена решения — `src/demo.ts` повторяет серверные расчёты: деление в копейках,
раздача остатка по одной копейке в порядке `userId`, жадный план переводов.
Это осознанное дублирование ради автономности демо; настоящие деньги по-прежнему
считает сервер. Демо отклоняет то же, что сервер (нулевые и дробные доли,
точные суммы, не сходящиеся с тратой), и так же раздаёт остаток: копейка
не достаётся участнику с долей 0.

Инварианты проверены тестами (`npm test`, `src/demo.test.ts`): сумма долей
равна сумме траты, сумма сальдо равна нулю, применение плана обнуляет все
сальдо, повторный ключ идемпотентности не создаёт дубль. `src/api.test.ts`
проверяет, что ключ идемпотентности приходит от вызывающего и не меняется
при повторе после `401`. Тесты гоняются в CI перед публикацией.

Подмена клиента живёт в `src/client.ts` — экраны импортируют оттуда и не знают,
с чем работают. Поэтому в компонентах нет ни одной ветки `if (demo)`.

## Что стоит знать о клиенте

**Деньги — строки.** `"300.33"`, не `300.33`. В JavaScript все числа —
`double`, и значение теряет точность ещё до показа пользователю. Поэтому суммы
приходят и уходят строками, арифметика остаётся на сервере.

**Повторная отправка защищена.** На создание траты и перевода клиент
шлёт `Idempotency-Key`. Ключ живёт до успешного ответа: форма траты запоминает
его вместе с моментом траты, кнопка «Я отдал» — для каждого перевода. Сорвалась
связь, и пользователь нажал «Сохранить» ещё раз — повтор уйдёт с тем же ключом
и тем же телом, сервер узнает его, и вторая трата не появится. Если форму
изменили, ключ новый. Повтор после обновления токена тоже идёт с прежним ключом.

**Токен обновляется сам.** На `401` клиент молча обновляет пару по
refresh-токену и повторяет запрос один раз. Одновременные `401` не порождают
несколько обновлений: refresh-токен одноразовый, и параллельное обновление
бэкенд счёл бы попыткой повторного использования — отозвал бы всю сессию.

**Ошибки показываются с `traceId`.** Бэкенд отдаёт их по RFC 7807, и
идентификатор из ответа ищется в логах сервера. Если пользователь прислал
скриншот, по нему находится конкретный запрос.

## Выкладка

Пуш в `main` собирает и публикует на Pages — `.github/workflows/pages.yml`.
Никакого Docker и реестра: на выходе статика.

Один раз нужно включить Pages в настройках репозитория: **Settings → Pages →
Source → GitHub Actions**.

Адрес бэкенда вшивается в сборку. По умолчанию боевой; переопределяется
переменной репозитория `API_BASE`.

### Свой домен

Сайт живёт на `splitly.toniess.dev`. Нужны три вещи:

1. **DNS** у регистратора `toniess.dev` — запись `CNAME` для `splitly`
   на `toniess.github.io.` (точка в конце обязательна).
2. **Settings → Pages → Custom domain** — вписать домен, дождаться проверки,
   затем включить **Enforce HTTPS**. Сертификат GitHub выпускает сам,
   обычно за несколько минут.
3. **`public/CNAME`** — уже в репозитории. Vite копирует содержимое `public/`
   в корень сборки, поэтому файл попадает в то, что уезжает на Pages.

Третий пункт неочевиден, но важен. При выкладке через Actions каждый деплой
подменяет содержимое сайта целиком, и без файла `CNAME` в самой сборке
привязка домена может слететь. Настройка в интерфейсе и файл в репозитории
должны совпадать.

Поддомен выбран не случайно: для него достаточно `CNAME`. Корневой домен
потребовал бы `A`-записей на адреса GitHub, а они меняются.

После смены домена не забыть разрешить его в бэкенде:

```
CORS_ALLOWED_ORIGINS=https://splitly.toniess.dev,http://localhost:5173
```

## Чего здесь нет

Редактирования и удаления трат — бэкенд их умеет (`PUT`/`DELETE /expenses/{id}`
с проверкой версии), клиент пока нет.

Выхода из группы — ручка есть, кнопки нет.

Обоих не хватает для полноты, но ни то ни другое не нужно, чтобы показать,
как работает деление счёта.
